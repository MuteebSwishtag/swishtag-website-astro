Enterprise purchasing works differently from ordinary ecommerce.

Frequently asked questions

Questions about PunchOut catalogs.

A practical overview for suppliers evaluating a procurement-to-ecommerce connection.

Ask us something specific →
What is a PunchOut catalog?

A PunchOut catalog connects a procurement application with a supplier’s online catalog. The buyer enters the catalog from procurement, selects products, and sends the cart back to the purchasing system to continue the organization’s internal process.

Which procurement systems can Swishtag work with?

Swishtag can work with PunchOut requirements involving procurement environments such as Coupa, SAP Ariba, JAGGAER, Oracle Procurement and Workday. The exact connection is reviewed against the buyer’s technical specification.

Which PunchOut protocols do you support?

Swishtag can implement cXML and OCI based PunchOut requirements. The protocol and transaction set used for a project depend on the buyer’s procurement environment and specification.

Can approved purchase orders create ecommerce orders automatically?

Where the buyer sends an electronic purchase order as part of the agreed workflow, Swishtag can map supported PO data into the supplier’s ecommerce or order-processing system.

Do we have to replace Shopify or our current commerce system?

Not necessarily. A PunchOut implementation can be built around an existing ecommerce store. We review the current storefront, catalog and customer setup before defining the integration approach.

Can you support multiple enterprise buyers and stores?

Yes. Multiple buyer connections or storefronts can be supported, but each buyer’s authentication, fields, testing process and transaction requirements should be reviewed individually.
